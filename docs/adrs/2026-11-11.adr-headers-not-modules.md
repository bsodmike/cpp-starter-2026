# Headers, not named modules, for v1

- Status: accepted
- Date: 2026-11-11

## Context

All three major compilers can now build `import std;`, but CMake still gates
`import std` support behind an experimental feature UUID that has changed
between releases, and IDE support is partial. Adopting named modules would also
change how every public header is consumed.

## Decision

Project code uses headers in v1. Public headers live under
`src/core/include/acme/core/` and are declared to CMake through a `FILE_SET` of
type `HEADERS`, so the install rules and the include paths come from one
declaration.

Set `CMAKE_CXX_SCAN_FOR_MODULES OFF` at the top of the root `CMakeLists.txt`.
CMake scans every C++20-or-later source for module dependencies by default,
which costs a `clang-scan-deps` (or `/scanDependencies`) run per translation
unit. With no target using modules, that is pure overhead.

One spike ticket re-evaluates modules once CMake stabilises `import std`.

## Consequences

- Builds skip the scanning pass entirely. This was verified both ways: the
  project builds correctly with scanning left on, so the setting is an
  optimisation and not a workaround for anything.
- The setting is scoped to this project's directory, so a parent project that
  pulls ACME in via `add_subdirectory()` and does use modules is unaffected.
- Consumers of the installed package decide for themselves. Because
  `acme::options` requires `cxx_std_23`, a consumer's own targets will have
  scanning enabled by CMake's default unless they also turn it off. That is
  their call, and nothing in the installed package depends on it either way.
- Delete the single `set()` line when modules are adopted; nothing else in the
  build depends on the choice.
