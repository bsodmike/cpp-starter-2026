# vcpkg in manifest mode for dependencies

- Status: accepted
- Date: 2026-11-11

## Context

The project needs reproducible dependency versions across three operating
systems and four compilers, resolved identically on a laptop and in CI. The
realistic options were vcpkg in manifest mode, Conan 2, CMake `FetchContent`,
and vendoring.

## Decision

Use vcpkg in manifest mode. `vcpkg.json` declares the dependencies and pins
every port version at once through `builtin-baseline`, a single vcpkg commit
hash. Test-only and benchmark-only dependencies sit behind vcpkg features
(`tests`, `benchmarks`) so a consumer building only the library does not pay for
them. The toolchain file comes from `$env{VCPKG_ROOT}` in a hidden `vcpkg`
configure preset that the real presets inherit.

Rejected:

- **Conan 2** is a reasonable tool, and remains the documented fallback if the
  team ever needs to publish prebuilt binaries to a private remote or wants
  many per-package build options. It is not CMake-native, which is the deciding
  factor for a repo whose entire interface is presets.
- **`FetchContent`** builds dependencies from source inside our build tree,
  which means their warnings, flags and targets land in our graph; it also has
  no version-locking story comparable to a baseline commit. Allowed only for
  the build's own tooling, never for project dependencies.
- **Vendoring** moves the maintenance and CVE-tracking burden onto us.

Never mix two package managers in this repo.

## Consequences

- Dependency bumps are a one-line change to `builtin-baseline`, reviewed as a
  single PR. The baseline is mirrored in `.tool-versions` so the devcontainer
  and CI check out the same vcpkg commit.
- CI needs a vcpkg binary cache to stay inside the 15-minute budget. The cache
  key includes the OS, compiler, preset and a hash of `vcpkg.json`, so a
  compiler or dependency change never reuses stale binaries. This matters
  especially across GCC major versions, which changed the ABI of some C++20
  library components.
- `VCPKG_ROOT` becomes a required part of the environment. The devcontainer sets
  it; a bare checkout needs it exported, which the README says.
- vcpkg fetches port sources over HTTPS from `codeload.github.com` among others.
  On a network that blocks it, `vcpkg install` fails even though `git clone`
  works. Air-gapped or restricted environments need an asset cache
  (`X_VCPKG_ASSET_SOURCES`) or a pre-populated binary cache.
