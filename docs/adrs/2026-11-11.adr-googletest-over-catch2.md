# GoogleTest as the test framework

- Status: accepted
- Date: 2026-11-11

## Context

The PRD named GoogleTest as the recommendation and Catch2 v3 as acceptable if
the team preferred it, and left the choice open.

## Decision

Use GoogleTest, pinned at 1.18.0 by the vcpkg baseline, behind the `tests`
feature in `vcpkg.json`. Tests register with CTest through
`gtest_discover_tests`, which enumerates cases at build time so each one is an
individual CTest entry. One test binary per library, labelled `unit`.

## Consequences

- `ctest -R <name>` addresses a single test case, and CTest parallelism applies
  per case rather than per binary.
- `gtest_discover_tests` runs the test binary during the build to enumerate
  cases, which adds a build step and needs a timeout (`DISCOVERY_TIMEOUT 30`).
  Under sanitizers that run is slower, which is the main cost of this choice.
- GoogleTest brings GMock, which we are not using yet but will not have to add
  later.
- Catch2 v3 remains a drop-in alternative: it offers `catch_discover_tests`
  with the same CTest integration, so switching would be a change to
  `tests/CMakeLists.txt` and `vcpkg.json` rather than a rewrite of the test
  bodies' structure. Revisit only if there is a concrete reason.
- `tests/.clang-tidy` relaxes `cert-err58-cpp`, because GoogleTest's `TEST()`
  macros create static objects whose constructors can throw by design.
